# Inkfold: ระบบขายหนังสือ Print-on-Demand (แบบ KDP)

ผู้ขายอัปโหลดสมุดระบายสีหรือหนังสือ แอดมินตรวจแล้ววางขาย ร้านพิมพ์เมื่อมีคำสั่งซื้อ
ระบบยังไม่เชื่อมธนาคาร ผู้ซื้อโอนแล้วแนบสลิป แอดมินยืนยันเอง และจ่ายเงินผู้ขายด้วยการบันทึกยอดโอน

## เริ่มใช้งาน

```bash
npm install
cp .env.example .env     # แก้ SESSION_SECRET, ADMIN_PASSWORD, ADMIN_INVITE_CODE
npm start                # หรือ npm run dev (รีโหลดอัตโนมัติ)
```

| ส่วน | URL | ใครใช้ |
|---|---|---|
| หน้าร้าน | `/` | ผู้ซื้อ (ไม่ต้องสมัคร สั่งแบบ guest แล้วติดตามด้วยเลขคำสั่งซื้อ + เบอร์โทร) |
| พอร์ทัลผู้ขาย | `/seller` · `/seller/register` · `/seller/login` | ผู้สร้างหนังสือ สมัครเองได้ |
| พอร์ทัลแอดมิน | `/admin` · `/admin/register` · `/admin/login` | ทีมงาน สมัครได้เฉพาะคนที่มีรหัสเชิญ |

บัญชีที่สร้างให้ตอนรันครั้งแรก:
- แอดมิน: ค่า `ADMIN_EMAIL` / `ADMIN_PASSWORD` ใน `.env` (ค่าเริ่มต้น `admin@inkfold.local` / `admin12345`)
- ผู้ขายตัวอย่าง (`SEED_DEMO=1`): `demo@seller.local` / `seller12345`

## การสมัครและล็อกอิน

- ผู้ขายกับแอดมินเป็นบัญชีคนละประเภท (`users.role`) ล็อกอินคนละหน้า อีเมลของผู้ขายใช้ล็อกอินฝั่งแอดมินไม่ได้ และกลับกัน
- แอดมินเพิ่มได้ 2 ทาง: ตั้ง `ADMIN_INVITE_CODE` แล้วให้ทีมงานสมัครที่ `/admin/register` หรือใส่ในฐานข้อมูลโดยตรง ถ้าเว้นว่างไว้ หน้าสมัครแอดมินจะปิด
- รหัสผ่านเข้ารหัสด้วย bcrypt (cost 12) และ session เก็บใน SQLite (คุกกี้ httpOnly, SameSite=Lax) เปลี่ยน session id ทุกครั้งที่ล็อกอิน
- ทุกฟอร์ม POST มี CSRF token ล็อกอินผิด 10 ครั้งใน 15 นาทีจะถูกพักชั่วคราว
- เปลี่ยนรหัสผ่านแล้วอุปกรณ์อื่นจะหลุดจากระบบ แอดมินระงับผู้ขายแล้ว ผู้ขายจะหลุดทันที และหนังสือทั้งหมดจะถูกซ่อน
- ใน browser เดียวล็อกอินได้ทีละบทบาท ถ้าจะทดสอบทั้งสองฝั่งพร้อมกัน ให้เปิดอีกฝั่งในหน้าต่าง incognito

## ขั้นตอนของหนังสือ

`ร่าง → รอตรวจ → วางขาย | ต้องแก้ไข | ไม่อนุมัติ` และแอดมินระงับเล่มที่วางขายอยู่ได้
- ส่งตรวจต้องมี: ปก JPG/PNG, เนื้อใน PDF, คำโปรย, ราคาไม่ต่ำกว่าค่าพิมพ์ และติ๊กยืนยันลิขสิทธิ์
- ถ้าผู้ขายแก้เล่มที่วางขายอยู่ เล่มนั้นจะกลับไปรอตรวจและถูกซ่อนจากหน้าร้าน
- แอดมินอนุมัติได้เมื่อติ๊กเช็กลิสต์ครบ 7 ข้อ (ขนาด/bleed, จำนวนหน้า, 300 dpi, ระยะขอบ, ลิขสิทธิ์, ปก, ช่วงอายุ) ประวัติการตรวจเก็บไว้ทุกครั้ง

## ขั้นตอนของคำสั่งซื้อ (ไม่เชื่อมธนาคาร)

`รอตรวจสลิป → (สลิปไม่ผ่าน → ผู้ซื้อส่งใหม่) → กำลังพิมพ์ → จัดส่งแล้ว (เลขพัสดุ) → ส่งถึงแล้ว` หรือยกเลิก
- เก็บเงินปลายทางได้ด้วย ค่าลิขสิทธิ์จะนับเมื่อพัสดุส่งถึงแล้ว
- ไฟล์ PDF สำหรับพิมพ์และสลิป ไม่เปิดให้คนทั่วไปเห็น: PDF เห็นเฉพาะเจ้าของเล่มกับแอดมิน สลิปเห็นเฉพาะแอดมิน

## ค่าลิขสิทธิ์

`ผู้ขายได้ = ราคาขาย × 60% − ค่าพิมพ์` โดยค่าพิมพ์ = 28 บาท (6×9 นิ้ว 20 บาท) + 0.45 บาท/หน้า ขาวดำ หรือ 2.2 บาท/หน้า สี่สี
แก้ตัวเลขได้ที่ `lib/catalog.js` ระบบล็อกค่าลิขสิทธิ์ต่อเล่มไว้ตอนที่มีคนสั่ง แอดมินโอนเงินผู้ขายจากแอปธนาคาร แล้วบันทึกยอดที่หน้า "จ่ายเงินผู้ขาย"

## โครงสร้าง

```
server.js            Express app, session, CSRF
config.js            อ่าน .env
db.js                SQLite schema + settings + sellerStats
seed.js              แอดมินแรก + ข้อมูลตัวอย่าง
lib/auth.js          session, bcrypt, rate limit
lib/auth-routes.js   login / register / logout / เปลี่ยนรหัสผ่าน (ใช้ทั้งสองพอร์ทัล)
lib/upload.js        multer: ตรวจชนิดไฟล์และขนาด
lib/catalog.js       ตัวเลือก ราคา สถานะ
routes/store.js      หน้าร้าน สั่งซื้อ ติดตาม
routes/seller.js     พอร์ทัลผู้ขาย
routes/admin.js      พอร์ทัลแอดมิน
routes/files.js      ส่งไฟล์แบบตรวจสิทธิ์
views/               EJS แยก store / seller / admin / auth
public/              CSS + JS เล็ก ๆ (คำนวณค่าลิขสิทธิ์ ยอดชำระ)
storage/             ฐานข้อมูลและไฟล์อัปโหลด (สร้างอัตโนมัติ, ไม่ commit)
```

## ก่อนขึ้น production

- ตั้ง `SESSION_SECRET` ยาวและสุ่ม, เปลี่ยนรหัสแอดมิน, ตั้ง `SEED_DEMO=0`
- รันหลัง HTTPS (Nginx/Caddy) แล้วตั้ง `COOKIE_SECURE=1`
- สำรอง `storage/` (มีทั้ง `inkfold.db` และไฟล์อัปโหลด)
- จุดที่ต่อยอดได้: เชื่อม payment gateway / ตรวจสลิปอัตโนมัติ, ส่งอีเมลแจ้งสถานะ, รีเซ็ตรหัสผ่านทางอีเมล, ตรวจขนาดหน้า PDF อัตโนมัติ
